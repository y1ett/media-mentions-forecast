# Прогноз медиа-активности по темам

Проектная работа по дисциплине «Интеллектуальный анализ данных». Тема №30 «Медиа и социальные данные».

**Прогнозируемый показатель:** число упоминаний темы за сутки — `mentions(тема, дата)` — на 1–7 дней вперёд.
Темы: ИИ и LLM, кибербезопасность, криптовалюты, электромобили, космос (задаются в `config.yaml`).

**Пользователь:** SMM-аналитик или редактор медиа — заранее видит, на какую тему ждать всплеска интереса,
и планирует публикации и ресурсы редакции.

## Источники данных

| Источник | Получение | Формат | Роль |
|---|---|---|---|
| Hacker News (Algolia API) | REST | JSON | **слабоструктурированный** (тексты); число документов по запросам темы = целевая переменная |
| Wikimedia Pageviews | REST | JSON | интерес аудитории (признаки) |
| GDELT DOC 2.0 | REST | CSV | объём мировых новостей (дашборд) |
| Habr RSS | RSS | XML | **слабоструктурированный** (русские статьи, дашборд) |
| Праздники RU/US | библиотека `holidays` | — | календарные признаки |

Данные открытые, имена авторов не хранятся. Подробно — [docs/architecture.md](docs/architecture.md).

## Структура

| Модуль | Что внутри |
|---|---|
| `src/config.py`, `src/http_client.py`, `src/db.py` | конфигурация (`config.yaml` + `.env`); HTTP с повторами и обработкой 429/5xx; схема DuckDB (`raw` → `staging` → `mart` + `meta`), журнал загрузок, водяные знаки |
| `src/ingest/` | инкрементальная идемпотентная загрузка: `hn.py`, `wiki.py`, `news.py` (GDELT, Habr), `calendar.py` |
| `src/processing/` | `text.py` — очистка текстов и текстовые признаки (VADER, слова-события, новизна лексики); `mart.py` — staging и витрина `mart.topic_daily`; `quality.py` — контроль качества данных |
| `src/features.py` | признаки (лаги, окна, календарь, Википедия, тексты) — один код для обучения и прогноза |
| `src/models.py` | 2 базовые модели + Ridge, случайный лес, LightGBM; валидация по времени и метрики |
| `src/registry.py` | реестр версий моделей и журнал экспериментов |
| `src/train.py`, `src/tune.py` | обучение, отбор признаков, прогноз, воспроизведение эксперимента, откат; автоподбор Optuna |
| `src/explain.py` | интерпретация: SHAP, перестановки, PDP, важность по периодам |
| `src/monitor.py` | мониторинг: PSI-дрейф, ошибка на новых фактах, правило переобучения |
| `src/dashboard.py` | дашборд Streamlit (6 вкладок, каждая отвечает на вопрос пользователя) |
| `src/__main__.py` | полный цикл одной командой |
| `tests/` | хранилище и загрузка; отсутствие утечки, валидация, модели, мониторинг |
| `docs/` | архитектура и источники, черновик отчёта, чек-лист сдачи |
| `reports/` | таблицы последнего обучения (сравнение моделей, абляция, важность, ошибки) |

## Стек

Python 3.11 · DuckDB (один файл без сервера, первичные ключи для идемпотентности) · requests, feedparser ·
scikit-learn, LightGBM · vaderSentiment · Optuna · Streamlit + Plotly · Makefile + cron · pytest.

## Запуск

```bash
make venv                 # окружение и зависимости
cp .env.example .env      # укажите CONTACT_EMAIL (User-Agent для Wikimedia)
make all                  # загрузка -> витрина -> качество -> обучение -> прогноз -> мониторинг
make dashboard            # http://localhost:8501
make test
```

Первая загрузка истории HN с 01.01.2025 — около часа (лимит Algolia ~10 000 запросов в час); её можно прервать
и продолжить. Повторные запуски догружают только новые дни.

Windows (без `make`): `py -3.11 -m venv .venv`, `.venv\Scripts\pip install -r requirements.txt`,
`.venv\Scripts\python -m src`, `.venv\Scripts\python -m streamlit run src/dashboard.py`.

| Команда | Что делает |
|---|---|
| `make ingest` / `build` / `dq` / `status` | загрузка / витрина / качество данных / сводка |
| `make train` / `tune` / `predict` | обучение / автоподбор / прогноз |
| `make monitor` / `retrain` / `rollback` | мониторинг / переобучение по правилу / откат версии |
| `make explain TOPIC=ai_llm DATE=2026-10-01 H=1` | объяснение конкретного прогноза |
| `python -m src.train experiments` / `reproduce <run_id>` | журнал экспериментов / воспроизведение |
| `python -m src.monitor --simulate-degradation ai_llm` | демонстрация реакции на ухудшение качества |

Расписание (cron, ежедневно): `0 6 * * * cd /path/to/project && make all >> data/cron.log 2>&1`

## Результаты (14.11.2026, история с 01.01.2025)

LightGBM на отложенной выборке (60 дней): ошибка **±35 упоминаний в день** (WAPE 21%), **на 30% точнее**
прогноза «как неделю назад». Подробно — [docs/report.md](docs/report.md).

## Ограничения
- Цель — упоминания на Hacker News (англоязычная IT-аудитория); документ под двумя запросами темы считается дважды.
- Для текстов сохраняется до 20 документов на (запрос, день); текстовые признаки отброшены отбором (не улучшили CV).
- GDELT (~3 месяца) и Habr RSS (только свежие статьи) не дают истории для обучения — используются в дашборде.
